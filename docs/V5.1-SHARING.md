# V5.1 — invitations et contexte du voyage

## Diagnostic du 6 octobre

Le site appelle aracne_trip_v5, mais la base expose seulement aracne_trip et aracne_trip_v2.
L'activation du partage échoue donc avant de pouvoir créer les liens.
L'installation de supabase/v5-upgrade.sql a été rejetée par le contrôle automatique d'approbation.
Aucune modification persistante de la base n'a été faite pendant cette correction.
Une autorisation explicite de l'utilisateur est nécessaire pour installer la migration de production
qui crée le RPC V5, accorde son exécution aux rôles navigateur et protège les documents migrés contre les anciennes écritures V4.

## Interface

- Un seul parcours: Inviter → Peut lire et modifier / Lecture seule → partage natif du téléphone.
- Activation du partage préparée à l'ouverture, avant le clic qui appelle navigator.share pour préserver le geste utilisateur sur mobile.
- Repli sur copie du lien si le navigateur ne propose pas de partage natif.
- Le message partagé inclut le nom du voyage.
- Bouton pour accéder aux noms des participants; l'organisateur choisit les destinataires dans WhatsApp ou une autre application.
- Un bandeau fixe au défilement indique voyage actif, rôle et synchronisation.
- Carte / Mappa / Map / Mapa reste visible sur mobile.
- Aide et introduction suivent le nouveau parcours.

## Synchronisation

- Une fenêtre de partage ne bloque plus l'application des mises à jour reçues.
- Les fenêtres d'édition actives restent protégées; une fenêtre d'édition fermée ne bloque pas le polling.
- La création relit la version canonique du serveur avant de fixer la base commune.
- Les credentials sont conservés si la connexion coupe entre création et lecture.
- Une création terminée après changement de voyage est mémorisée pour le bon voyage, pas appliquée au voyage actif.
- L'absence du RPC V5 produit une explication persistante au lieu d'un message générique fugitif.

## Vérification

npm ci && npm test

Tests quatre langues, deux sessions simulées, conflit explicite, appel navigator.share pour les deux droits,
nom actif, mise à jour avec fenêtre de partage ouverte, création canonique et erreur PGRST202 explicite.
Ce ne sont pas des tests sur deux téléphones ni un test de bout en bout sur le service V5 réel,
qui doit d'abord être installé avec autorisation.

## Activation après autorisation explicite

Le 6 octobre, l’utilisateur a autorisé l’installation en production.
`supabase/v5-upgrade.sql` a été exécuté et le cache de schéma PostgREST rechargé.
`tests/v51.live.cjs` a ensuite relié trois instances isolées de l’application au vrai RPC V5:
création neuve, organisateur → participant, participant → organisateur, lecture synchronisée,
refus serveur d’écriture avec lien lecture, notes de groupe synchronisées, notes privées exclues.
Le voyage synthétique créé pour ce test a été supprimé à la fin.
Les alertes advisors SECURITY DEFINER exposé sont attendues pour l’API sans compte par clés capability;
les tables privées sont protégées par RLS sans politique d’accès direct.
Ces tests ne remplacent pas la vérification du menu natif de partage sur un iPhone/Android physique.
